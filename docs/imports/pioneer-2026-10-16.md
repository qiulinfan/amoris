## Selection decisions and limits

- Keep the implemented paths and meaningful controls. Superseded timing sessions and invalid
  development-viewport observations are not current performance claims. Concise final results,
  methods, regression fixtures and limitations remain; raw runs and captures stay in ignored
  output or separately authorized results storage.
- Share only immutable, component-built collision geometry. The weak table holds no game state;
  mutation copies the shape first. The integration accepts cold BVH reconstruction and tests
  altered-shape isolation, cold restores and fork trajectories. Large collider specification
  hashing still costs a tick; this does not establish a complete level-scale solution.
- Keep Rapier. The source's Jolt recommendation is not a backend migration. Unity is only a
  benchmark dependency, not an engine requirement. PhysX measurements and outcome comparisons
  requiring clearance remain in the private source; the public document contains methods only.
- Keep fork lookahead explicit. Its no-fork control scores better on the measured course, so it
  does not replace the reference skipper or establish LLM fork-tool performance. A fresh script
  branch still exceeds the source's one-frame budget on R1.
- Keep full-size rendering as the default. Temporal upscaling has camera-motion and thin-feature
  limits. Transparency sorts instance centres, has no geometric refraction or transparent motion
  vectors, and does not add transparent neural materials.
- The AMD diagnosis identifies driver behavior; the integration does not repair that driver.
  A successful matrix run does not guarantee the driver will never compile another wrong program.
- Adopt the `amoris` identifiers without old-interface compatibility. Frozen hash domains,
  historical output, pinned Git object paths and external names retain their recorded bytes.
  Historical-build reproduction keeps the rename tool; Pioneer's temporary synchronization
  exception and its tests are no longer needed in Amoris.

- The committed viewport is rebuilt locally with build paths remapped; it contains no user-home

The intermediate series is checked with `cargo check --workspace --all-targets --locked` in a
separate checkout; editor changes additionally run TypeScript checks. Small implementation,
regression, tool and specification commits preserve their dependencies. The engine-wide identifier
rename remains atomic because the crate graph, scripts, schemas and generated viewport must agree.

Platform corrections are folded into their owners: readback locks are released before a refused
map can synchronously call back; the strict scale-return test uses an unscaled control with the
same output-size history so LOD hysteresis is held constant; complete TAA test cases are serialized
because concurrent test devices on M5 can be lost. Validation errors and unexpected device loss
fail those tests. These changes retain all image assertions. The final build-tool qualification
also discovers Homebrew LLVM consistently and uses Python with `websocket-client` for CDP.

R1 performance figures retain their original hardware and dates. Local correctness checks are not
new Windows performance measurements. Detailed logs stay in ignored `out/integration/` and
`out/check/`; source and benchmark records contain no file-verification inventory.
